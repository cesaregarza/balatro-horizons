## Change

- Versioned `tools_v4`: one complete, stable tool catalog; current IDs and constraints live in
  the masked observation. OpenAI `allowed_tools` restricts the current phase without changing
  the catalog. Both provider parsers still reject unavailable tools; the existing authoritative
  action validator still rejects stale observations, invalid IDs, targets and illegal ordering.
- Stable developer instructions and frozen skill index on initial calls and helper follow-ups.
  A single explicit breakpoint ends after this reusable prefix. Dynamic state, budgets, memory
  and helper outputs follow it. No previous_response_id or opaque provider memory is introduced.
- Same public information, paging and bounded working memory for both providers. Anthropic
  receives equivalent stable system text and schemas; this change does not enable Anthropic caching.
- Explicit OpenAI cache pricing: ordinary input, cache reads and cache writes are disjoint.
  Reserve using the highest configured input rate. Incomplete or inconsistent usage keeps the
  full reservation. v4 requires GPT-5.6+ and explicit cache rates; long-context pricing above
  272K remains blocked. Existing v1/v2/v3 behavior stays available, including legacy Luna caching.
- UI and CLI registration expose the new interface and separate prices. Existing saved players
  keep their version; do not rewrite old manifests or migrate them silently.

The full catalog increases serialized request bytes (median 15,841 → 21,308 in the offline
comparison). That is a deliberate cache-stability tradeoff, not input compression. All 99
reconstructed requests fit the existing 32,768 conservative bound; the largest was 29,202.
Byte counts are not provider token counts. No filler text was added to manufacture cache hits.
