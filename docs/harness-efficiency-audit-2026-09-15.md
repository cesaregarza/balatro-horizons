# Transcript efficiency audit — 2026-09-15

The next Terra run would benefit most from clearer public-state and budget presentation. These transcripts do **not** establish that tools_v3 is too large, that more reasoning would improve play, or that the harness caused a particular share of either outcome. The largest measured recurring input costs are instructions and tool schemas; the most consequential observed ambiguity is mixing unearned skip tags with active blind effects.

## Priorities before another paid run

### 1. Distinguish offered skip tags, acquired tags, and actual prices

**Measured presentation ambiguity, alongside independently demonstrable model errors.** Luna request sequence 4 / decision 0 and Terra sequence 68 / decision 8 put `['D6 Tag', 'Rerolls in next shop start at $0']` inside `revealed_blinds[].effects`. Native conversion explicitly collects `effect`, `tag_name`, and `tag_effect` into the same list (`engine/native_state.py`). Acquired tags instead appear as bare keys in `persistent_effects`.

The correct action semantics were already present: recorded `select_blind` says, “This does not award its skip tag,” and `skip_blind` explicitly awards it. Terra sequence 68 also shows `shop_reroll_cost: '5'`, money 5, and no persistent tag. Its sequence 70 action note nevertheless says “Use free rerolls.” Money then falls to zero; the next reroll is rejected at sequence 79. Thus the harness exposed contradictory-looking presentation, but did supply the correct price and action description.

This mistake recurred rather than resolving permanently. Terra decision 18, request 158, shows Obelisk price 8 and no persistent tag alongside a Negative Tag in the upcoming Small Blind effects. Action 160 calls it “Free Negative Obelisk.” Decision 51, request 432, shows Abstract Joker price 4, no edition effect, and no persistent tag; action 434 calls it free Polychrome. Later memory repeats the unearned edition. Those are model misreadings of available fields, not absent price/edition data.

**Proposed check:** give offered skip rewards explicit labels and activation conditions, preserve boss effects separately, and distinguish acquired pending tags. Replay recorded public observations offline and verify that fighting never describes a skip reward as acquired, and that request prices remain identical. Do not alter native mechanics or retroactively relabel old journals. This changes model-visible presentation and needs versioning, focused tests, and the normal release/recertification process before activation.

### 2. Expose monetary headroom and separate bytes from priced tokens

**Confirmed budget-information omission.** The prompt asks the model to win “within the displayed budgets,” but Terra request 493 / decision 58 delivers only:

```json
{"game_actions":1442,"provider_calls":1937,"helper_calls_this_decision":0,"helper_calls_remaining":8}
```

No remaining dollar allowance or next-call reservation is supplied. The run stops two actions later for monetary exhaustion despite abundant displayed action/call allowance. A model cannot infer the actual stopping boundary from those counters. This does not prove it would choose better with monetary information.

Every Terra request reserves $0.180224: 32,768 × $2.50/M input plus 8,192 × $12/M output. The median settled estimate is $0.012386 and the maximum $0.0239655. At stop, $0.164695 remains under the $1 ceiling; another maximum reservation would require $1.015529 total. The reservation is released on settlement, not billed 65 times. At a $10 cap, this same worst-case reservation can strand less than approximately 1.8% of the cap, so it is less urgent than at $1.

There is a non-obvious coupling: `providers.py` rejects when `len(json.dumps(body).encode()) + 4096 > max_input_tokens_per_call`, while `runner.py` uses that same limit as a **token count** for reserving money. Reducing the input ceiling to 8,192 because measured inputs stay below 5,000 tokens would reject these otherwise valid 10.6–19.3 KB request bodies. Keep the byte safety bound distinct from any proposed token-aware reservation.

**Proposed checks:** display authoritative remaining monetary headroom, next maximum reservation, and affordability; retain strict episode/campaign enforcement. Test those fields against settlement and unknown-usage cases. Separately test any tokenizer-aware reservation against complete serialized provider inputs. Lowering the output cap to match this small sample risks truncating later difficult decisions: 1,034 is an observed maximum, not a safe universal limit. Budget-display and reservation algorithm changes require source validation and recertification; a higher authorized cap alone does not require pretending these changes already exist.

### 3. Address repeated input and almost-unused caching with measured experiments

Terra delivered 60 distinct tool schemas across 65 requests. `tools_for` inserts the observation ID and current object IDs into tool enums; schemas therefore change across actions, even within a phase. Dynamic enums help prevent stale-ID actions, so removing them has a real correctness tradeoff.

Actual Terra input categories are **238,403 cache-write tokens, 1,396 cached-read tokens, and 195 residual ordinary tokens**. Every response reports cache writes. Only response sequence 87, the second follow-up at decision 9, reports a cache read. Reads represent 0.58% of all input. Schema changes and request assembly are plausible contributors to poor cache reuse, but this trace alone does not identify cache-key construction or prove causation.

Using the documented disjoint-category rates of $2/M ordinary input, $0.20/M cached input, $2.50/M cache writes, and $12/M output gives **$0.8319967**, only **$0.0033083 (0.40%)** below the recorded conservative $0.835305. Applying $2/M to every input token would miss the observed write premiums. These are usage-derived estimates, not an invoice. Pricing sources, checked by the coordinator on 2026-09-15: [pricing](https://developers.openai.com/api/docs/pricing) and [Terra model](https://developers.openai.com/api/docs/models/gpt-5.6-terra).

Counterfactual ordinary-input-only pricing at identical token counts would be $0.715308, about $0.116689 below the category estimate. That is a conditional arithmetic comparison, not demonstrated savings or a verified supported Terra caching configuration. Luna explicitly disabled caching; Terra used default caching. Their cost ratio cannot be interpreted purely as different model token efficiency.

**Proposed checks:** first expose actual cache-write/read categories and settled-versus-reserved amounts in reporting. Then reconstruct candidate stable instruction/tool layouts offline, measure bytes, and preserve current-ID validation. Test cache modes or schema redesign only in separately authorized matched live conditions; record cache rates, rejection rates, token use, and outcomes. A schema/prompt/caching revision changes the information/transport condition and must be versioned and validated. Do not claim old tools_v2 savings from unmatched live trajectories.

### 4. Improve feedback clarity; treat teaching and forced retrieval as separate experiments

The recent-event previews contain truncated serialized observations and action IDs, rather than an explicit last-action chip/cash delta or resolved hand classification. For example, Luna request 36 shows prior chips 156 inside a truncated preview and current chips 248, so the +92 consequence is recoverable but must be calculated. The full record remains retrievable. Neutral public-state deltas could make consequences easier to inspect without ranking moves; native scoring breakdown availability remains unverified.

Terra's four helpers were complete single pages: resources at decision 9 / sequence 84 (386 bytes), deck knowledge at decision 33 / sequence 281 (1,140 bytes), and hand levels at decisions 37 and 53 / sequences 318 and 451 (877 bytes each). The resources lookup repeated already visible information after an affordability error. The other sections were legitimately deferred at their phases. No page loop, guide rejection, or context-clear/reload cycle occurred. Five follow-up provider calls after helper/error exchanges cost $0.0663645; this is observed follow-up spending, not a causal savings estimate.

Memory was small, frequently rewritten, and sometimes wrong. Terra decision 39 / operation 338 records “compact <=3-card Two Pairs”; decision 46 / operation 394 calls three Clubs a flush; decision 57 / operation 487 expects about 4,089 from three selected Clubs, while the next observation shows 1,095. The provider had current ranks, hand levels and the Onyx text “when scored.” Luna decision 2 / request 20 had T/T and 4/4 available but operation 22 selected K/T/T/5/4, leaving one 4 behind; the saved memory falsely called that Two Pair. Luna decision 4 / response 37 expected about 55 for A/Q/J/T/4; actual gain was 16. Four unused discards were visible. These are rules/application errors, not demonstrated missing-card information.

**Proposed checks:** distinguish model plans/expectations from observed consequences in notes; show lossless public action deltas if implemented; measure recurrence of contradicted beliefs. A brief authoritative scoring/rules kernel, phase-specific skill suggestions, enforced skill loading, or a score-preview tool may be useful experiments, but they change knowledge/assistance and cannot be sold as neutral compression. No evidence here establishes optimal play, a need to force more reasoning, or how much help a guide would have provided.

## Fairness and validation limits

The older Luna tools_v2 episode used 105 calls for 98 actions, with 424,287 input and 27,765 output tokens, before a harness context-construction failure. It predates the current guide/context condition. Its six inspection results ranged from 7,733 to 11,204 compact bytes, versus Terra's 386–1,140; different sections, states, and helper policies make that an illustration of mechanisms, not a controlled efficiency result. Existing matched offline reconstructions in [focused-context documentation](harness-focused-context.md) establish request construction only.

Both primary models used medium reasoning and automatic returned summaries. Summaries are model-generated accounts, not raw reasoning, and their absence does not mean no reasoning occurred. Output totals already include reasoning; it must not be counted again as an extra fee. Reducing reasoning is not established as an improvement by this audit.

The known Terra export failure at response sequence 385 comes from a credential-shaped substring inside opaque encrypted response content. This audit did not dump, weaken the scanner for, or export that content. `tool_messages` reconstructs public calls/results; it does not forward provider-owned opaque reasoning. Export reliability is a separate issue from model-input efficiency. Selected report artifacts can pass the existing scanner without altering the original export policy. No private seed exclusion check was run because private manifests were intentionally not read.

No provider/game calls, live continuation, native recertification, service changes, runtime/config edits, or Hermes tests were performed. The helper ran successfully against all three verified journals. This audit supports prioritizing clearer tag and monetary-budget presentation, then measuring stable-input/cache changes under a versioned protocol; it does not justify activating untested harness changes immediately before the next run.

## Cache diagnostics follow-up and artifact validation

All 65 Terra requests lack `prompt_cache_options.comparison_response_id`; all 65 responses lack `prompt_cache_diagnostics`. Thus the recorded trace cannot attribute misses to schema changes. The coordinator verified the official [GPT-5.6 cache diagnostics guide](https://developers.openai.com/api/docs/guides/prompt-caching/diagnostics): on a subsequent already-authorized generation request, supply the last completed response ID as `prompt_cache_options.comparison_response_id`, and retain the returned `type`, `reason`, `comparison_reusable_tokens`, and `cache_missed_tokens`. This diagnostic comparison is compatible with `store:false`, is metadata-only, and does not inject previous conversation content or change caching. Diagnostics have no additional charge; generation still costs money. Comparison records are short-lived, and only the first classified miss reason is returned. Use an episode-local comparison baseline; do not use `previous_response_id` as a substitute. This is proposed instrumentation, not an implemented change or authorization for a probe.

Final offline checks passed: all three recorded journal heads remain unchanged; both selected report artifacts pass the existing generic export privacy scanner; the dedicated audit helper compiles and successfully produced the three-episode numeric report. Private-seed exclusion and full Terra export were intentionally not retried. No new runtime or configuration changes were made.
