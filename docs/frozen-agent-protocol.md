# Frozen agent protocol

Work package B3 adds `agent-protocol-v1`. Before the first decision, the runner
captures the exact UTF-8 prompt bytes, delivered rules-kernel variants, tool
catalog and interface policy, model settings and prices, episode allowances,
knowledge hash, memory/retention policy, and executable implementation hash.
Each episode owns an immutable private `agent-protocol.json` artifact. Its hash
and episode reference appear in the append-only `episode_start` event, every
checkpoint, terminal summary, and public export. Child manifests also reference
the parent protocol. Root manifests created before runtime startup are not
rewritten: the start event is the authoritative snapshot commitment.

Context construction consumes this snapshot. Editing prompt files during a run
or before an ordinary branch cannot change that continuation's instructions.
The original UTF-8 text (including whitespace) is preserved; delivery applies
the existing `.strip()` convention. Tools v4/v5 use the frozen catalog. Older
interfaces retain state-specific schemas generated by the pinned executable
code, preserving their observation-ID and handle constraints.

Provider configurations and episode limits are deep copied. Branches inherit
the original knowledge and protocol; incompatible model settings or episode
allowances are rejected before game construction. Human interventions keep the
parent context policy and remain assisted, ineligible continuations. Changing
models is not silently accepted as an ordinary continuation. An explicit
protocol-change intervention remains future work.

Operator permission and shared campaign funding remain outside agent episode
allowances. They still require current authorization and the locked spending
ledger; snapshot inheritance never authorizes spending. Historical episodes
remain readable. A legacy checkpoint without an agent-protocol snapshot cannot
claim a frozen-protocol branch and is disabled with a specific missing-snapshot
error rather than retroactively rewriting its evidence.

## Fingerprint responsibilities

The agent protocol hash includes prompt bytes, schemas, knowledge identity,
model settings, prices, limits and policies. The existing native implementation
fingerprint still conservatively covers engine, public projection, legality,
storage, runner, service, branch restoration, scheduling and executable agent
code. These domains intentionally overlap: provider/budget changes can affect
execution or evidence integrity. This release does not narrow those executable
dependencies to avoid recertification.

Prompt files alone leave the native executable fingerprint because they are now
immutable episode data and are not read by restoration. Fresh runs get a new
protocol hash; old branches read their original snapshot. Editing executable
code invalidates continuation compatibility and native evidence. The change to
fingerprint semantics itself requires native recertification for this release.

The two hashes do not establish provider-side reproducibility: a model alias
may change upstream, stochastic responses may differ, and only empirical native
replay establishes the supported restoration phases. Opaque provider material
remains private and is omitted from public exports under the B2 policy.

## Bounded release smoke

The existing OpenAI smoke helper now accepts `--agent`, `--campaign`,
`--authorized-episode-cap`, `--authorized-total-cap`, and `--env-file`.
Defaults retain the historical Luna ceilings. A new campaign uses a separate
durable ledger; configuration revisions within it share that ledger and retain
unknown-usage reservations. Ceiling arguments must reflect explicit operator
permission; choosing an argument does not establish authorization.

Example after authorization and native release gates:

```bash
.venv/bin/python scripts/smoke_openai.py --config private/release-smoke.json \
  --agent terra --campaign protocol-release-20260916 \
  --authorized-episode-cap 5 --authorized-total-cap 10 \
  --env-file /tmp/tmpkey --dry-run
```

Replace `--dry-run` with `--allow-paid` only within that authorized task.
The helper reads only the named API key and never executes credential-file text.

## Verification

Offline regression tests edit prompt files after the first helper request and
before branching across all five interfaces, verify later delivered prompts and
branch protocol hashes, and reject snapshot tampering, missing legacy snapshots,
and changed episode allowances. Additional integration tests cover configuration
copying, provider round trips, frozen knowledge, journals and branch isolation.
Native release and paid-provider results are recorded separately in the release
report; synthetic tests do not establish native or paid-provider fidelity.
