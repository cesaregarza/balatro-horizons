## What changed for runs and branches

New episodes snapshot their exact prompt, rules kernel, tool catalog, model
settings and prices, knowledge identity, episode allowances, and memory policy.
Every checkpoint references the frozen protocol. Editing a prompt cannot change
an active run or its ordinary continuation. Model or allowance mismatches are
rejected before constructing a branch game. Legacy traces remain readable;
checkpoints without the new protocol artifact cannot claim frozen-protocol
branching. See [B3 details](frozen-agent-protocol.md).

Within one decision, `tools_v5` returns provider-native reasoning and tool-call
items with correctly linked tool results. A game action ends that continuation;
the next decision uses public history and bounded agent-authored memory. Both
providers receive the same tool catalog and local phase validation. The
OpenAI-only generation restriction in `tools_v4` remains part of that older
version. Public exports remove opaque continuation material. See
[B2 details](../CHANGELOG.md).

Campaign funding no longer becomes a spurious agent loss. An unfunded next slot
creates no episode or game; an in-flight funding interruption remains unresolved.
The first funding stop survives reruns and crash recovery. Episode resource
allowances remain distinct evaluation conditions. See
[Part A details](campaign-budget-fix.md).

## Deployed workbench

- Local: <http://localhost:8765/>
- Phone on the same Tailscale network: the operator's private tailnet route.
- User service: `balatro-horizons.service`.
- Persistent service definition:
  `/root/.config/systemd/user/balatro-horizons.service`.
- Credential source: a credential file readable only by the backend and
  authorized smoke helper. No credential value is included in this handoff.

The service definition survives a stop/start. It is not enabled for automatic
boot, and the temporary credential file and WSL Windows-launch context remain
session-dependent. After reboot, recreate the key file if needed, restore the
Windows launch context with `scripts/configure_workbench_session.py --apply`
from a Windows-connected WSL shell while idle, then start the user service.
Do not assume that reusing a Linux service definition restores Windows mods or
save isolation; use the existing startup diagnostic if context changes.

The backend listens on loopback. The existing private Tailscale Serve route on
8443 points to it; the unrelated 443 route was preserved. No public Funnel was
enabled. WSL Chromium could not resolve MagicDNS, so the phone-sized HTTPS check
used the existing `BH_WORKBENCH_IP` override to resolve the real hostname to its
tailnet IP. TLS and origin checks remained enabled. This verifies the real
HTTPS route, not a repair of WSL's DNS configuration or a physical phone test.

## Remaining limits and recovery

- Live provider evidence covers OpenAI Terra only. Anthropic continuation and
  error handling were tested with mocked transports, not paid Anthropic calls.
- Rendering suppression/headless equivalence and accelerated execution are not
  certified by this release.
- Provider model aliases and stochastic responses are not made reproducible by
  freezing local protocol bytes.
- Before changing executable engine/harness code, stop the worker and respect
  the resulting native certificate invalidation. Prompt-only edits create a new
  protocol for new runs while existing runs retain their original snapshot.
- The pre-release runtime/settings/evidence/frontend backup and verification
  logs are in `private/release-backup-20260916-B3/`. A rollback must restore a
  matching source/runtime/evidence set, not just old certificate files.
- Read-only progress is available through `scripts/smoke_openai.py --status
  --campaign protocol-release-20260916`. This records review exposure, as do
  full-run transcript summaries and exports. It makes no paid requests.
